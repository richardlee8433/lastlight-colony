# 測試計畫

一次跑完：`npm test`（`tests/run-all.sh`），報告在 `tests/out/report.md`，截圖在 `tests/out/*.png`。
需要 Playwright 與 Chromium；影像檢查需要 python3 + pillow（沒有就略過那一項）。

## 1. 靜態檢查（`tests/static.ts`，不開瀏覽器）

| 編號 | 檢查 |
|---|---|
| S01 | 每個劇情觸發條件都有對話內容，每段對話都有觸發條件 |
| S02 | 每句台詞有中英文、說話者與路線標籤合法、沒有殘留的 `{…}` 參數；日誌也要中英文 |
| S03 | 每章目標 id 不重複（舊存檔的打勾紀錄靠它），英文目標數量與中文一致 |
| S04 | 第 4 章：合成室排第一，營區與醫療艙第一次襲擊後才出現，目標 id 維持舊值 |
| S05 | 介面字串中英文都不是空的（中文量詞 `unit.*` 英文可以空） |
| S06 | 每棟建築、升級節點、研究都有英文 |
| S07 | 玩家看得到的文字沒有「出生率」 |
| S08 | 每棟建築與改建形態都有手繪圖 |
| S09 | 殖民者、陸戰隊、突擊隊、微光獸的 sprite sheet 都在 |
| S10 | 小人轉向：巡邏 2 分鐘，30～165Hz、縮放 2／3 倍，轉向次數一樣且很少（高更新率螢幕不能左右閃） |

## 2. 模擬（`sim/balance.ts`）

四條路線（合作／抵抗 × 保留／放棄異晶）各用機器人玩到結局，必須都點亮信標（或造好船）。
合作＋保留那一輪同時存下各章存檔（`SNAPDIR`），給瀏覽器測試用：
`ch2`～`ch6`（每章進來 2.5 分鐘）、`ch4-preraid`、`ch4-postraid`、`ch6-choice`、`end`。

模擬器不會讀文字，所以敘事順序、介面問題要靠下面的瀏覽器測試與人工試玩。

## 3. 瀏覽器測試（`tests/e2e.cjs`）

| 編號 | 檢查 |
|---|---|
| E01 | 新遊戲：開場畫面之後出現第一段對話，有文字、沒有殘留參數 |
| E02-2～6 | 每章存檔：任務欄章節正確、計數與清單一致、沒有殘留參數、沒有頁面錯誤（各章截圖） |
| E03 | 第 4 章：第一次襲擊前看不到營區、醫療艙目標，襲擊後出現 |
| E04 | 逃生艙：紀念堂蓋好前在建造列，蓋好後退役 |
| E05 | 2000×1100 寬螢幕縮到最小、拖到兩個角落（截圖，交給影像檢查判定黑邊） |
| E06 | 科技樹開著時研究倒數照常前進 |
| E07 | 按 P 暫停：出現暗幕、資源不動；再按恢復 |
| E08 | 英文介面：任務欄沒有中文 |
| E09 | 存檔與讀檔：重新整理後章節一致 |
| E10 | 微光獸、企業突擊隊襲擊：交火（截圖）、擊退戰報 |
| E11 | 第 6 章抉擇：討論播完後跳出「這是誰的家？」與兩個選項 |
| E12 | 兩種結局：結局對話播完才出現結局畫面，標題正確 |
| E13 | 日夜：白天環境光正常；夜晚變暗變藍、建築亮燈 |
| E14 | 影子落在右下（翻到地上、往右斜）；清晨比中午長；夜晚消失 |
| E15 | 設定頁「日夜變化」：夜晚時關掉立刻變白天，重新整理後仍然關著 |
| E16 | 清晨時有小人站在建築影子裡而變暗 |
| E17 | 效能：手機尺寸、CPU 降速 4 倍，比較日夜開／關的每幀場景運算時間（多出超過 4 ms 算失敗，數字存在 tests/out/perf.json） |

## 4. 影像檢查

E05 的截圖在畫面邊緣取樣，接近純黑就判定有黑邊。

## 還是要人工看的

- 劇情與目標的敘事順序是否合理（例如第 4 章「襲擊前就叫你蓋營區」）
- 美術風格是否一致、建築大小是否協調
- 數值手感（太快、太慢、卡關感）
- 手機直式的操作
